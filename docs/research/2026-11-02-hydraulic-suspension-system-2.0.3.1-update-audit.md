## 1. Significant new systems — distinguish real physics writes from claims

**HSS20-01 — ECAS truck air rear suspension:** `KIND_AIR=3`, `setupAir` selects truck shop category/type, detects 2–3 longitudinal axle groups using wheel world→local Z positions, picks rear-half wheel suspensions with real `suspTravel`, and uses an `airProfile` (spring/damper, level rate, manual height, auto reset above 30 km/h). **Real physical wheel `positionY` and spring/damper control**, not merely HUD. Type detection, axle count, tandem/dual tires and truck center-of-mass layout are heuristics, not proof every truck has realistic air suspension. Excludes >3 detected axles by default; misclassified 6×4/8×4 possible without a real vehicle trace.

**HSS20-02 — profile/capability control:** user overrides per **vehicle model**: `auto`/absent, `level`, `pendular`, `off` stored under `modSettings`; `HydraulicSuspension.reconfigureModel` re-runs setup for all currently loaded copies of a model. `manualHeightAll=false` can override per-brand realistic restriction but is explicitly labeled not realistic. Better UX for supported-vs-unsupported hardware but manual `level` is a user choice and does not prove the vehicle geometry actually has a suitable actuator. New injector recognizes custom vehicle-type names by store category but excludes combines; validate special tractors converted to custom type.

**HSS20-03 — new UI and save:** complete HSS window, contextual modes/telemetry/alerts, model override and Zasty HUD coexistence; replaces old in-game General settings menus. Adds explicit `#loaderOff` savegame schema registration (fixes potential HSS 1.1 serialization-warning issue). Per-user modSettings schema `settingsVersion=12` **unchanged between archived v1.1 and new 2.0.3.1**, so older 1.1 settings should not be auto-recreated solely due to new version; missing keys load defaults. Preserve a backup because profile/layout changes can still affect interpretation. Vehicle mode/manual offset/loaderOff save persistence still needs actual 2× reload test. Config file controls are host/local: do not assume server+client synchronized physics policy.

**HSS20-04 — Realistic Physics 1.20.x interoperability:** `realisticPhysicsCompat(self,wheels)` looks for `wheel.physics.stOrig` (RP sets it while overwriting suspension during `WheelPhysics.loadFromXML`). If found and `rpCompat=true`, for **all wheels of eligible tractor** it restores each 4 damping fields only when below source `stOrig`, and caps `forcePointRatio` at `max(originalRatio, configuredLimit=0.7)`. This is a **true field-level adapter** that attempts to preserve RP weight/hop while preventing a weak damper + soft HSS spring from extreme pitch/roll. The previous separate [RP 1.20.2 source audit](2026-10-23-realistic-physics-1.20.2.0-full-stack-audit.md) confirms RP broadly sets `forcePointRatio=0.9` and weak damper values. A direct, narrow compatibility effort by the HSS author deserves recognition.

**HSS20-05 — but RP adapter is one-shot, not a stable lease (reproduced isolated Lua):** `pw.hssRpFixed=true` prevents subsequent correction for same wheel. Exact-source Lua test with original dampers **27/32/24/37** and RP-mutated **1/1/1/1**, original force ratio 0.56 / current 0.9: first adapter call restored the four dampers and capped current ratio to **0.7**. After another external overwrite back to damper 1/force 0.9, *second call did nothing* (still 1/0.9). Therefore guarantee depends on load/reapplication order. This is not proof RP continuously overwrites in normal gameplay. Adapter also does not negotiate with **MoreRealistic** spring/damping owner. Setting `rpCompat=false` is opt-out. If detected late, HSS may never run a fresh RP normalization for a wheel already initialized; study actual calling paths.

**HSS20-06 HIGH — previous MR wheel owner suppression still present:** `claimWheel(pw)` installs a per-wheel overwrite of `setSuspensionMultipliers`: external callers can have desired values recorded without being forwarded, and the wrapper is not an explicit removable/leased owner. The source-owned HSS physics can be useful *alone*, but it still conflicts architecturally with an MR-compatible adaptive suspension contributor. The RP fix does **not** prove HSS+MR compatibility. If benchmarking, compare actual spring/damping and wheel travel under one tractor, one loader, player→AI→park.

**HSS20-07 HIGH for untrusted MP — mode event still lacks requester authorization (Lua harness):** `HydraulicSuspensionModeEvent:run(connection)` merely checks vehicle/spec exists, calls `HydraulicSuspension.setMode` and rebroadcasts; no farm/controller permission or server-side manual-offset cap. Isolated Lua mock: foreign-farm client set another farm's suspension to MODE_MANUAL with `manualOffset=1.2`, and the handler accepted/broadcast. No actual multiplayer exploit proved; the previously documented HSS 1.1 defect has not been fixed. Avoid public untrusted MP until upstream authority enforced. In contrast RE PTO StateEvent checks controller ownership.

**HSS20-08 MEDIUM — model global change and overrides:** UI `canEditServer` uses `g_server ~= nil or g_currentMission.isMasterUserConnected`, a coarse session flag, not a per-request permission check. Per-model override changes happen through local settings and `reconfigureModel`, without a bespoke server-authoritative event/synchronization transaction; multiplayer policy may diverge. Test only on trusted singleplayer first. `reconfigure` and other physics changes rely on `pcall` fail-open paths: silent failures may leave partial state; observe per-wheel diagnostics rather than UI labels alone.

**HSS20-09 MEDIUM — new hydraulic/truck physics remains an approximation:** ECAS uses normalized wheel spring/damper/position offsets and inferred axle masses, not physical air volume/compressor pressure, anti-roll valves or finite hydraulic energy. JCB rear suspension, loader boom ride control and cabin camera remain separate performance/ownership domains. A 2.0.3.1 release label is not proof all added systems were tested against MR/Mud/Reifen/RMS.

## 2. Our stack and options

| Domain | HSS 2.0.3.1 relationship | Recommendation |
| --- | --- | --- |
| **MR** | Controlled wheel spring/damper/height and suppressing foreign `setSuspensionMultipliers` calls still overlap MR. | Test external **HSS as active suspension owner** on one proven vehicle in isolated mod profile before inventing a new RC spring arbitration bridge. |
| **Realistic Physics (Rónai Márk)** | New source-specific `stOrig` adapter, physically restores damper/caps force-point at startup, one-shot. | Valuable precise upstream integration; pairwise A/B and order test; do not assume RP now safe in user's full MR/Mud/Reifen stack. |
| **Mud + Reifen** | No direct new friction/sink/radius owner; wheel load/height changes alter contact/sink and structural radius interpretations. | Measure physical load and uneven-ground contact. No automatic RC tire patch. |
| **RMS 0.13.0.1** | RMS component wear/steering/terrain-impacts and hydraulics load respond to wheel/chassis movement. HSS spring/position can change input strain; no new RMS wear writer in HSS. | Test chassis/hydraulic damage noise on controlled rough ground and loader payload. |
| **RE PTO** | Shaft and operator RPM remain RE/RC/MR/RMS-owned. HSS visual/moving-tool front axle and shaft geometry is distinct from shaft speed/power. | No RE PTO code change. |
| **RE Terrain V3** | No direct `TerrainDeformation` heightmap writer. HSS changes wheel forces, contact geometry and load; compare RE ruts only after controlled physical A/B. | Avoid changing terrain engine assumptions based on unvalidated suspension-mod data. |
| **4x4 Traction System 2.1** | Different field owner (diff graph/CTIS) but jointly mutate wheel dynamics. | Do not combine new 4x4 + HSS + RMS + Reifen in the first A/B; isolate changes. |

## 3. Practical decision and study

**Most promising from the pair of mods:** **HSS 2.0.3.1**. Permit an **isolated singleplayer experiment** on a cloned save with **one proven front-suspension tractor**, then one truck for ECAS and one real loader. Crucially, test HSS OFF/ON with MR present and absent to identify whether MR suspension requests are lost or simply delegated. Also test RP adapter when RP is added alone as a distinct experimental profile (not all physics mods at once). Record selected actual wheel spring/damper, wheel positionY/travel, forcePointRatio, axle articulation, ride height, body roll, driver/worker handoff, logs and frame time. Test save+reload twice and any model override.

**RE absorption priority:** clean-room **ActiveSuspension** with hardware proof, bounded stroke, proper spring/damping owner arbitration; optional **TruckAirSuspension** capability and load-based truck ECAS policy; separate **LoaderRideControl** with verified actuator and **CabIsolation** visuals. Before absorbing, external mod may already be good enough for gameplay; do not reimplement everything by default. The RP normalization is a positive lesson in *targeted compatibility at the actual physical field*, but one-shot restoration is not enough as a future general contract. Avoid code/asset copying absent rights.
