# PTO V1.5 — MR 500-rpm pump operating target vs tractor 540-rpm gear

Date: 2026-10-09
Status: fixed in `feat/pto-v1-5-observability` (PR #39); validate by Lua/XML/ZIP CI, real-game operation still unproven.

## Reproduction: two uploaded sessions

1. `log(20261009-200711).txt` — RE terrain-integration `3e3554a43d1c3c6b3305d609a799d8ffb48a7ca4` + RC main `ad7461fb`, MR `0.26.10.08`. `180-90 DT` repeatedly reports `required=500` with `source=POWER_CONSUMER_PTO_RPM` and `mismatch=true` at 540 and 1000 despite successful mode/throttle changes. Later `6R 155` also reports `required=500`.
2. `log(20261009-201318).txt` — RE V1.5 observability `227d13763e40d539a351b0dcae75ded985960512` and same RC main; PTO and MR/RMS bridges active. No detailed operator/requirement messages (verbose off), so this session **cannot independently identify the attachment or physical spray failure**.
3. The logs include the MR overrides for both attached devices and do not show a direct code error naming either sprayer. Do **not** conflate a UI compatibility warning with proven game logic preventing spray. No duplicate PTO engine owner detected.

## Root cause in MR source

MoreRealistic `quadural/MoreRealistic_FS25@b38d5667e073505255cd7ce170ab568616a91221`:
- `MoreRealistic/data/overriding/vehicles/hardi/aeon5200.xml`: `powerConsumer#ptoRpm=500`, `neededMaxPtoPower=7.5` kW.
- `MoreRealistic/data/overriding/vehicles/berthoud/vantage4300.xml`: `powerConsumer#ptoRpm=500`, `neededMaxPtoPower=12` kW.

These are **pump operating targets**. 500 RPM can be achieved on an actual 540-rpm tractor gearbox by reducing the engine RPM to ~92.6% of its nominal PTO rating, subject to engine/pump requirements. No new 500 shaft mode or over-1000 requirement is needed. HARDI pump technical documentation separately describes 540-rpm PTO connection and 500-rpm normal operating speed. See https://www.hardisprayer.com/product/pump-1303-c-w-pto-540-rpm/ .

## Targeted implementation (no universal RPM rounding)

- Retain `requiredRpm=500` as MR's actual operational demand and add a separate `requiredGearboxFamilyRpm=540` for the two exact, source-evidenced MR XML identities.
- Profile only applies when `spec_powerConsumer.ptoRpm==500`. If another version declares 540/1000 or no RPM, the native value (or unknown classification) takes precedence. No inferred hydraulic/E-PTO connection for generic consumers.
- Native `540` and `540E` now share the matching **gearbox family**, while `1000`/`1000E` remain mismatches for these pumps. Economy option remains selected by operator, not automatically assumed for the worker.
- A worker selects a fitted 540 conventional mode before engaging; MR/GIANTS independently decides engine speed and keeps `ptoRpm=500` and power/torque calculation unchanged. For 500, autonomous GIANTS/MR RPM target should follow 500 rather than a hard-coded 540 family if source uses the raw consumer value.
- Read-only contract: `state.requiredShaftRpm=500` (raw target), `state.requiredGearboxFamilyRpm=540` (selector), `state.mismatch` uses the family; no changes to the mechanical gear ratio, consumed PTO torque or actual engine governor. Event log prints both values when verbose logging is active.
- Mixed requirements, unsupported 750/900/1300, and unknown 500 devices remain fail-closed; this is not generic tolerance-based compatibility.

## Test scope / limitation

Regression harness asserts both sprayer profile identities, native-version guard, 500-vs-540 distinction, AI gear selection and restoration, unprofiled-500 failure, 500+540 conflict and no injected 500 gear. This closes the **classification/UI/AI selection** defect. A sprayer failing to turn on/apply product may still have a distinct cause in GIANTS/MR, available material, or physical PTO engagement. We must not claim to have proven it repaired just from CI; use one targeted playback only if the sprayer remains inoperable, not a full repeat of prior PTO smoke tests.
