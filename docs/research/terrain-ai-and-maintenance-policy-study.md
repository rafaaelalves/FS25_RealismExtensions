# Terrain actor and passive-maintenance policy study

Status: implementation foundation complete; passive maintenance actuator intentionally deferred.

## Runtime trigger

R7 runtime build:
`1ad037ef2975860be49f7d5a9704bd078424ccee`

The user observed that a hired worker can progressively damage a field with persistent RE ruts while performing AI-generated manoeuvres. Runtime supports the observation:

- recovery while the cultivator is physically working is already protected: `activeCultivatorRutSkips=4925`;
- outside that protected work phase the same root vehicle continues writing persistent terrain;
- one late 5 s window accepted +857 rut brushes;
- cumulative writer attribution reached `root 180-90_DT=49688`;
- stationary-wheelspin terrain writes were present (`stationaryBrushes=84`, `stationaryApplied=0.102 m`);
- the recovery controller itself remained healthy.

Interpretation: the missing abstraction is not recovery power but **actor policy**. RE currently treats a path generated by a hired worker exactly like player-authored driving.

## Actor-policy principle

Do **not** globally disable terrain deformation for helpers.

A normal worker pass must retain the same:
- wheel load;
- footprint;
- ground pressure;
- wetness response;
- slip/shear response;
- MR/Mud upstream physics.

Otherwise hiring a worker becomes a realism exploit.

Instead, persistent RE terrain writes are suppressed only for explicit AI-navigation pathology states:

### AI field-worker turn / corner-cut

GIANTS exposes field-worker state including:
- `getIsFieldWorkActive()`;
- `getAIFieldWorkerIsTurning()`;
- `getAIFieldWorkerIsCornerCutOutActive()` where available.

A turn/corner-cut trajectory is generated by the AI course planner. Its exact wheel path is therefore not player-authored terrain use. R8 policy suppresses only RE persistent rut writes while this state is active.

### AI stationary wheelspin / stuck state

A helper may sit and spin while the AI drive strategy tries to recover. Waiting time must not become permanent excavation.

If an AI actor has near-zero body motion while wheel surface speed indicates stationary wheelspin, RE persistent writes are suppressed.

### Straight/ordinary AI motion

No multiplier is applied. Actor identity by itself does not change physics.

The earlier idea of generic reduced AI shear/slip was rejected because it would make the same machine physically different merely because the driver changed.

## Actor classification

`TerrainActorPolicy.lua` classifies the combination root as:

- `PLAYER`
- `AI_FIELD`
- `AI_GENERIC`

Native GIANTS methods are preferred, with conservative fallback to `spec_aiFieldWorker`.

External AI systems such as Courseplay/AutoDrive may later need normalized compatibility state if they do not expose the native GIANTS signals. That belongs in RC/provider integration rather than model-name or mod-specific branches in RE.

## Telemetry

New runtime line:

`TerrainActors | samples/brushes/depthM PLAYER=... AI_FIELD=... AI_GENERIC=... suppressedTurn=... suppressedSpin=...`

This is intended to make ordinary gameplay sufficient for validation. The user should not need to construct a dedicated worker test matrix.

## Territorial responsibility model

A separate `TerrainMaintenancePolicy.lua` classifies who may eventually maintain RE-owned terrain debt.

Fail-closed mapping:

| Territory | Passive maintainer |
|---|---|
| player-owned farm | NONE |
| another human/other farm | NONE |
| NPC field | NEIGHBOR |
| public/non-buyable world | MUNICIPAL |
| buyable but unowned land | NONE |
| unknown | NONE |

The important safety rule is that **unowned does not automatically mean public**. A buyable forest/lot must not be silently restored by a municipal system.

NPC-field detection is based on GIANTS FieldManager/farmland semantics, including `farmlandIdFieldMapping`, field ownership state and NPC association.

## Passive maintenance actuator — design only

No passive terrain mutation is enabled by this change.

When implemented, maintenance should operate only on existing RE SpatialHistory debt rather than scanning the full map:

1. take a bounded batch of active history cells;
2. classify territory at each cell;
3. require an eligible maintainer (NEIGHBOR or MUNICIPAL);
4. require old enough causal RE debt;
5. reject loaded-contact/current-activity regions;
6. estimate the current local target plane exactly as recovery does;
7. apply bounded target-plane convergence;
8. reconcile/retire verified cells.

This preserves player-authored topography because the target is the current surrounding surface, not original map height.

### Neighbor maintenance

NPC fields should recover as part of their simulated management lifecycle, not instantly after damage.

Preferred semantics:
- delayed;
- low-frequency;
- stronger around field-work lifecycle transitions;
- eventually restores severe accidental AI/player traffic damage enough that NPC farms do not degrade forever.

### Municipal maintenance

Public maintenance must be even more conservative:
- only eligible surface categories such as road/gravel/compacted dirt;
- never blindly alter waterways, rock, construction, landscaping or arbitrary public terrain;
- delayed and incremental;
- bounded per update/day;
- no whole-map scan.

### Player land

No passive maintenance. The player's equipment and explicit recovery mechanics remain responsible for consequences on the player's farm.

## Testing philosophy

From this point the preferred validation loop is ordinary gameplay plus telemetry.

Manual directed testing is reserved for:
- a new physical actuator;
- a safety invariant;
- a regression;
- a class that runtime telemetry proves is not being detected.

The project should not require the user to test every cultivator, plow, subsoiler and helper combination manually.


## Implemented periodic maintenance architecture

Passive maintenance is now implemented.

### Calendar trigger

The executor subscribes to `MessageType.PERIOD_CHANGED`. This event is used by GIANTS for persistent period-based aging and provides the desired low-frequency maintenance cadence.

`FINISHED_GROWTH_PERIOD` was investigated because FieldManager subscribes to it for NPC field lifecycle updates. It was not selected as the main trigger because maintenance is a land-responsibility abstraction rather than a crop-growth operation, and tying it to growth updates would create a less predictable cadence.

### Persistent age

SpatialHistory v6 adds:
`maintenanceAgePeriods`.

Rules:
- new/fresh wheel interaction sets it to 0;
- PERIOD_CHANGED increments it once, bounded to 255;
- save/load persists it;
- recovery/retirement removes it naturally with the cell.

This avoids per-frame timestamps and makes save/reload behavior deterministic.

### Queue construction

On PERIOD_CHANGED:
1. iterate only active history cells;
2. increment maintenance age;
3. ignore cells below min causal rut debt;
4. classify territory, caching the result by farmland id;
5. enforce 1-period neighbor / 2-period municipal minimum age;
6. spatially bucket eligible cells;
7. keep the oldest/deepest representative per bucket;
8. cap at 256 neighbor + 128 municipal patch seeds;
9. interleave both classes into a bounded queue.

No terrain sampling, target fitting or TerrainDeformation object is created during this scan.

### Execution

Ordinary update starts at most one task when:
- server-authoritative;
- recovery is not structurally in-flight;
- TerrainWriter has no pending work;
- no loaded-contact wheel overlaps the patch.

Each task revalidates:
- history still exists;
- age still qualifies;
- responsibility did not change;
- full patch remains under the same maintainer;
- municipal surface is DIRT/GRAVEL.

Then it uses the same robust local target-plane estimator and bounded TARGET semantics as agricultural recovery.

### Memory lifecycle

Successful maintenance calls the same verified patch reconciliation used by the recovery architecture:
- inspect only causal history cells inside the patch;
- compare actual height with the fitted current target plane;
- clear logical debt only within tolerance;
- SpatialHistory retirement removes dormant cells from the LRU and persistence snapshot.

Thus maintenance is also history garbage collection backed by physical convergence, not a metadata-only cleanup.

### Conservative municipal scope

Without an explicit road network mask, only public GRAVEL/DIRT terrain paint is eligible.
HARD terrain normally produces no rut debt; MUD is excluded because it may represent natural wetland rather than maintained public infrastructure.
