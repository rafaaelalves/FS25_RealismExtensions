# Architecture decision records

Use this directory for decisions that future contributors are likely to question.

Each ADR should contain:
- context/problem;
- considered options;
- decision;
- consequences/tradeoffs;
- evidence/version scope;
- what would justify revisiting it.

Do not use ADRs for routine implementation notes.
- [ADR 0006](./0006-rds-functional-absorption.md) — proposed capability-level absorption of RDS start UX and pneumatics without duplicating RMS/ADS/MR mechanical ownership.
